# SarcasTone — Multimodal Sarcasm Detection Using Text and Speech Prosody

*Beyond Words. Understanding Intent.*

B.Tech CSE research project. Compares **text-only**, **speech-only** and **multimodal (feature-level fusion)** sarcasm
classifiers on the **MUStARD** dataset, with a React dashboard and a FastAPI backend. Every metric shown in the UI is read
from `results/metrics.json`, which is written by the training script. Nothing is hardcoded.

## Run it (Windows / macOS / Linux)

Prerequisites: Python 3.10+, Node.js 18+, and (for audio) [ffmpeg](https://ffmpeg.org) on your PATH.

```bash
# 1. Backend (terminal 1)
cd backend
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m uvicorn app.main:app --port 8000 --reload     # API docs: http://localhost:8000/docs

# 2. Frontend (terminal 2)
cd frontend
npm install
npm run dev                                             # open http://localhost:5173
```

The text-only model and its evaluation are already trained and included, so the app runs immediately.

## Enabling speech-only and multimodal models (one command)

The MUStARD audio is not in the Git repo; it is a separate download (Hugging Face, ~GBs). This script downloads it,
extracts a 16 kHz mono WAV per utterance, then extracts features and trains/evaluates all three models:

```bash
python scripts/setup_audio.py                         # downloads automatically
python scripts/setup_audio.py path/to/mmsd_raw_data.zip   # or use a zip you already have
```
Then restart the backend. Until this is done, the Speech/Multimodal analysis still shows real measured acoustic features
(pitch, energy, MFCC, pauses, rate) but **no sarcasm prediction**, and the Models page says the models are not trained.

## Method
* **Data**: `dataset/sarcasm_data.json` from github.com/soujanyaporia/MUStARD (690 utterances, 345 sarcastic / 345 not, 21 speakers, 4 shows). Castro et al., ACL 2019.
* **Text model**: lower-casing + cleaning, TF-IDF (1–2 grams, min_df=2) + Logistic Regression, plus an explicit
  sentiment-contrast feature (VADER compound sentiment of the sentence's first half vs. second half) so a
  "positive setup, negative payoff" sentence like "wonderful day, already had an accident" has a dedicated signal
  instead of relying entirely on individual word weights, which a bag-of-words model can't connect across a whole
  sentence. Trained on MUStARD's 690 lines plus ~28.6k generic English headlines (News Headlines Sarcasm Dataset,
  Misra & Arora, CC0, downloaded to `dataset/external/`, not in git) added only to each fold's *training* data — the
  reported MUStARD accuracy is still evaluated on MUStARD-only held-out speakers, never contaminated by the external
  data. Removing English stopwords from the vectorizer was tried and measured worse on the large holdout
  (80.8% vs. 84.3% accuracy) despite looking like an improvement on one example sentence, so it was reverted —
  a reminder that a handful of manual examples isn't a reliable signal for this kind of change.
* **Speech model**: audio is high-pass filtered (removes DC offset/rumble) and loudness-normalized to a
  target RMS before feature extraction, so recordings made on different mics/gains land in a comparable
  range to the training clips. Then: 47 Librosa features (pYIN F0 stats, RMS, ZCR, spectral
  centroid/rolloff/bandwidth, 13 MFCC mean+std, pause stats, speaking-rate approximation) + Random Forest
  (300 trees). The API also reports a `domain_shift` score (z-distance of the live recording's features
  from the training distribution) and the UI shows a warning when a recording looks statistically unlike
  the training audio, so a near-50/50 result is clearly flagged as low-confidence rather than presented
  as a precise measurement.
* **Multimodal**: late fusion, not joint feature-level fusion — the text model's probability (the same
  headline-augmented model above) and the speech model's probability are combined by a small 2-input
  logistic-regression meta-model. A single model trained on raw TF-IDF + prosody features together would
  be stuck at MUStARD's 690 audio-labeled rows (headlines have no audio to pair with), which kept
  multimodal exposed to the same narrow-vocabulary problem the text model had before it was fixed. Late
  fusion lets the text side keep its full headline-augmented training while the prosody side keeps its
  own dedicated Random Forest; only the small meta-model is fit on the 690 rows where both exist.
* **Evaluation**: 5-fold `GroupKFold` by speaker (speaker-independent). Vectorizers/scalers are fitted inside each training fold (no leakage). Metrics from pooled out-of-fold predictions; seed 42.

## Current results (generated by `python -m app.ml.train`, see `results/metrics.json`)
| Model | Accuracy | F1 | ROC-AUC |
|---|---|---|---|
| Text-only (MUStARD held-out) | 49.0% | 0.351 | 0.446 |
| Text-only (generic-English held-out, n=4,293) | 84.3% | 0.838 | 0.924 |
| Speech-only | 62.3% | 0.596 | 0.676 |
| Multimodal | 62.0% | 0.593 | 0.677 |

The text model is trained on MUStARD's 690 lines *plus* ~28.6k generic English headlines from the News Headlines
Sarcasm Dataset (Misra & Arora, CC0) — see "Text model" below. This widens its vocabulary past 4 sitcoms' dialogue
at some cost to MUStARD-specific fit (the first row is lower than training on MUStARD alone would give), but the
model that's actually deployed and used by the Studio is evaluated far more informatively by the second row: accuracy
on ~4,300 headlines the model never trained on (`results/metrics.json`'s `text_only_generic_english_holdout`), which
is a large enough sample to trust, unlike eyeballing a handful of example sentences. It's still measuring a specific
register (headline-style English, not spoken conversation), so treat it as a meaningful improvement, not a guarantee
on everything you might type — individual sentences can still be misclassified, especially short ones where a single
word happens to dominate the model's vocabulary.

**Interpretation.** Under speaker-independent evaluation the TF-IDF text model performs at chance level, and that stays
true whether or not the external headlines are added — MUStARD sarcasm leans heavily on delivery/context the model
can't see from a single line of dialogue. With a plain random split the same (MUStARD-only) model reaches 59.4%, which
indicates that much of that apparent signal is speaker/show vocabulary rather than sarcasm
(`results/exploratory_text.json`, produced by `experiments/exploratory_text_variants.py`). Adding dialogue context gave
54.6% in that exploratory run. These exploratory variants are not the official result. Small data (690 samples) means
all estimates are noisy. Here, speech-only prosody is the strongest signal on the official MUStARD metric and
multimodal fusion does not beat it outright; this is a real, reportable finding, not a target to be reverse-engineered
by re-tuning until multimodal wins.

## Limitations
* Small, sitcom-only dataset; may not generalise to natural speech.
* No ASR: for multimodal analysis the user types the transcript (labelled "user-provided").
* Speaking rate is an energy-peak approximation. Sentiment uses the general-purpose VADER lexicon.
* No text-voice "mismatch" score is shown, because no validated method was implemented.
* openSMILE, DistilBERT and PyTorch were intentionally left out to keep the project laptop-friendly; Librosa covers the prosody features.
* Not for real-world decision making.
