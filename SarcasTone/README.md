# SarcasTone — Multimodal Sarcasm Detection Using Text and Speech Prosody

*Beyond Words. Understanding Intent.*

B.Tech CSE research project. Compares **text-only**, **speech-only** and **multimodal (feature-level fusion)** sarcasm
classifiers on the **MUStARD** dataset, with a React dashboard and a FastAPI backend. Every metric shown in the UI is read
from `results/metrics.json`, which is written by the training script. Nothing is hardcoded.

## Run it (Windows / macOS / Linux)

Prerequisites: Python 3.10+, Node.js 18+, and (for audio) [ffmpeg](https://ffmpeg.org) on your PATH.

```bash
# 1. Backend (terminal 1)
cd backend
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m uvicorn app.main:app --port 8000 --reload     # API docs: http://localhost:8000/docs

# 2. Frontend (terminal 2)
cd frontend
npm install
npm run dev                                             # open http://localhost:5173
```

The text-only model and its evaluation are already trained and included, so the app runs immediately.

## Enabling speech-only and multimodal models (one command)

The MUStARD audio is not in the Git repo; it is a separate download (Hugging Face, ~GBs). This script downloads it,
extracts a 16 kHz mono WAV per utterance, then extracts features and trains/evaluates all three models:

```bash
python scripts/setup_audio.py                         # downloads automatically
python scripts/setup_audio.py path/to/mmsd_raw_data.zip   # or use a zip you already have
```
Then restart the backend. Until this is done, the Speech/Multimodal analysis still shows real measured acoustic features
(pitch, energy, MFCC, pauses, rate) but **no sarcasm prediction**, and the Models page says the models are not trained.

## Method
* **Data**: `dataset/sarcasm_data.json` from github.com/soujanyaporia/MUStARD (690 utterances, 345 sarcastic / 345 not, 21 speakers, 4 shows). Castro et al., ACL 2019.
* **Text model**: lower-casing + cleaning, TF-IDF (1–2 grams, min_df=2) + Logistic Regression.
* **Speech model**: 47 Librosa features (pYIN F0 stats, RMS, ZCR, spectral centroid/rolloff/bandwidth, 13 MFCC mean+std, pause stats, speaking-rate approximation) + Random Forest (300 trees).
* **Multimodal**: feature-level fusion (TF-IDF ⊕ standardized prosody) + Logistic Regression.
* **Evaluation**: 5-fold `GroupKFold` by speaker (speaker-independent). Vectorizers/scalers are fitted inside each training fold (no leakage). Metrics from pooled out-of-fold predictions; seed 42.

## Current results (generated by `python -m app.ml.train`, see `results/metrics.json`)
| Model | Accuracy | F1 | ROC-AUC |
|---|---|---|---|
| Text-only | 48.8% | 0.475 | 0.494 |
| Speech-only | not trained yet (audio not available when this was built) | | |
| Multimodal | not trained yet | | |

**Interpretation.** Under speaker-independent evaluation the TF-IDF text model performs at chance level. With a plain random
split the same model reaches 59.4%, which indicates that much of that apparent signal is speaker/show vocabulary rather than
sarcasm (`results/exploratory_text.json`, produced by `experiments/exploratory_text_variants.py`). Adding dialogue context
gave 54.6% in that exploratory run. These exploratory variants are not the official result. Small data (690 samples) means all
estimates are noisy. Multimodal is not guaranteed to beat text-only; report whatever your run produces.

## Limitations
* Small, sitcom-only dataset; may not generalise to natural speech.
* No ASR: for multimodal analysis the user types the transcript (labelled "user-provided").
* Speaking rate is an energy-peak approximation. Sentiment uses the general-purpose VADER lexicon.
* No text-voice "mismatch" score is shown, because no validated method was implemented.
* openSMILE, DistilBERT and PyTorch were intentionally left out to keep the project laptop-friendly; Librosa covers the prosody features.
* Not for real-world decision making.
